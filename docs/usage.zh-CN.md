# 使用 Genesis

<p><a href="usage.md">English</a> &nbsp;·&nbsp; <strong>简体中文</strong></p>

你跟 coding agent 说话，agent 去操作 Genesis。没有要配置的东西，也没有要你记的命令：在 agent 里打开你的项目，提下面两种要求之一就行。还没装的话，先看[安装说明](install.zh-CN.md)。

## 看一次改动

```text
/genesis review main
```

Codex 里对应的是 `$genesis`。直接用大白话问也可以，什么语言都行：

```text
我最近这次提交改了什么？会不会弄坏别的功能？测试能兜住吗？
开 PR 之前，帮我对照 main 看看这个分支。
看看我还没提交的改动，有没有风险。
```

`review` 后面跟的是要对比的分支、tag 或提交。跟分支名时，看的是你的分支从它分出来之后已经提交的改动；还没提交的改动，包括新文件，都不在其中。不写的话，agent 会对比你这个分支开始的地方。

没提交的改动要单独看，对比的是最近一次提交：照上面第三个例子那样直接说就行。Git 还没跟踪的新文件，agent 判断属于这次改动时会算进去。Python 项目里，没算进去的新文件报告会列出来；其他语言的项目不会列，由 agent 在开始前自己检查有没有新文件。

没有可比较的内容时（自那个版本以来没有改动，或者本地仓库里没有这个版本），agent 会直接说明，并建议换一个版本、看没提交的改动，或者画整个项目。

你会得到每一处行为上的变化，用产品的语言说明，并且每一处都带着：

- 能走到它的入口和流程；
- 一个测试结论（见下面的[测试结论](#测试结论)）；
- agent 读这处改动和调用它的代码时发现的风险。

agent 还会把改动落到的流程描述出来，这样页面上的改动就标在有业务名称的步骤上。Python 项目里，它最多描述三条，挑改动最多的；受影响的流程更多时，它会说明其余几条还只是按代码画的，并问你要不要接着描述。如果你只要快速的答复，它就跳过这一步。其他语言的项目里，agent 会先描述改动所在的流程，再说明改动，因为改动要靠流程里的步骤才能落到图上。Python 项目之前画过地图时，看改动会从最近一张 agent 自己找出过入口的地图出发：沿用那张地图的入口，以及它把入口归到流程里的方式，所以只要启动那条流程的代码都还在，改动就会落在地图上原来那条流程里。也可以让它改用一份已提交的地图副本，比如 Genesis EDD 和 Spec 一起保存的那份，这样项目的每个克隆得到的流程都一样。

## 画整个项目

```text
/genesis map
```

或者说：“把这个项目的业务流程画出来”“这里的下单流程是怎么走的”。

agent 会找出进入系统的入口（路由、命令、后台任务、处理函数），把它们归成一个个业务流程，再把每个流程写成步骤和分支。这些流程合起来就是项目的业务流程图，下文简称地图。项目大的时候，它先画主要流程，再问你要不要画剩下的。

## 结果在哪里

Genesis 把结果写在你项目里的 `.genesis/out/latest/`：

| 文件 | 是什么 |
| --- | --- |
| `view.html` | 要打开的页面。每个流程一张图，改动标在图上。 |
| `summary.md` | 同一份结果的文字版，可以直接贴进 PR。 |
| `graph.html` | 同一张地图的简易大纲页，不需要脚本。 |
| `business-map.json` | 地图的数据。看改动时其中的 `mode` 是 `change`：地图只覆盖这次分析过的部分，有了规划之后只有规划的流程，不是整个项目的地图。早先版本写的地图没有 `mode`，两种都有可能。 |
| `change-report.json` | 改动和测试结论的数据。只有看改动时才有。 |

`business-map.json` 还在 `source` 下记录了地图读的是哪一版代码：提交号（`revision`）、是否连同未提交的改动一起读了（`worktree_dirty`）、是否有本该读的文件被略过，比如超过大小上限的文件（`integrity_status`），以及读过的每个文件和它内容的 SHA-256 摘要（`files`），不含内容本身。摘要按文件在这个提交里存的样子算，也就是 `git show <revision>:<path>` 输出的内容，即使你的检出转换了换行符也一样；有未提交改动的文件，摘要按读到的内容算。要知道地图和之后某个提交是否还对得上，就用同样的方法拿那个提交里的文件比对摘要：摘要不同或已经不在的文件，在地图生成之后改过。之后新加的文件不在列表里。用 git-crypt 这类 Git 过滤器转换的文件，在 Git 的索引不能确认它没变时，会算作有未提交的改动；先运行一次 `git status` 更新索引，再重新 prepare。

`latest` 里只有最近一次运行的结果：看改动会把之前的地图换掉，画地图也会把之前看改动的结果换掉。每次运行的结果还另外留在它自己的目录 `.genesis/out/<session id>/` 里，文件相同。

agent 做完后会把 `view.html` 的路径告诉你。请用浏览器打开，不要用编辑器的预览：页面要靠脚本运行。页面是自包含的，打开时不从网络加载任何东西。项目的 `origin` 在 GitHub 上、提交也已推送时，页面上有两处会访问 GitHub，而且只在你点击之后：步骤背后的代码和提交号链接到 github.com；看改动时，点页面顶部的提交范围，会向 GitHub 的公开 API 查询两个版本之间的提交，发送的是仓库名和两个提交号。

Python 项目画地图时，agent 还会在一开始就把页面在你的浏览器里打开（有浏览器可开的话）。这时页面上只有 Genesis 找到的入口，每个入口一行。页面不会自己刷新，agent 做完后请刷新一下。其他语言的项目一开始没有内容可看，等 agent 给出路径后再打开。

设置了环境变量 `GENESIS_NO_BROWSER` 时，页面一律不会自动打开。如果 agent 跑在另一台机器上（SSH、容器或云端），那里没有浏览器可开。把 `view.html` 拷到你自己的机器上，或者直接在那边读 `summary.md`。

## 页面怎么看

- 每个流程画成步骤和箭头。判断步骤会画出它的分支。
- 点开一步，能看到它做什么、背后是哪段代码。如果项目的 `origin` 在 GitHub 上、提交已经推送、那边的代码也和本地一致，这一步给出的是 GitHub 上的文件链接，而不是代码本身。
- 看改动时，每处改动都标在它所属的步骤上，带着它的含义、测试结论、得出结论的理由和风险。结论依据的是哪些测试，写在 `summary.md` 和 `graph.html` 里，页面上不列。
- 不属于任何步骤的改动，以及被改动删掉的流程，放在“流程之外”这一块。`summary.md` 把这些改动列在 “Changes not on the map” 下面。
- 只涉及 Genesis 没有分析的改动文件（比如 Dockerfile）的风险，页面上不显示，`summary.md` 和 `graph.html` 会连同这些文件一起列出。
- 选中一处改动时，“可能影响”标在这条流程后面、改动可能走到的结果上。它是顺着流程的箭头推出来的，不是发现的问题。
- 一个业务领域的查询和维护流程收在一行里，比如“另有 3 条查询和维护流程”，点开就能看到。不属于任何领域的流程放在“其他流程”下面。角上带数字的卡片代表几步合在一起，点开就会显示这几步。
- 步骤上可能有一个标记：agent 在这一步或这一步上显示的改动里记了风险，就是“风险”；否则，有改动的步骤只要测试结论不是“有行为验证”，就是“待验证”。
- 步骤上的“待确认”或“未知”表示证据还不足以完全支持这一步，原因列在 `summary.md` 的 “Uncertain” 下面。它和测试结论里的“覆盖待确认”不是一回事。
- “代码结构”表示流程还没描述：流程用它的路由或函数命名，步骤用代码行命名。“未归纳”表示流程已经有名称，步骤还没描述。
- 只有 agent 描述了某一步的数据形状，这一步才有“输入 / 输出”页签。那是 agent 从代码里读出来的形状，不是校验过的契约。

### 测试结论

Genesis 只读你的测试，从不运行它们。所以任何结论都不代表某个测试通过了。

| 页面上 | `summary.md` 里 | 含义 |
| --- | --- | --- |
| 有行为验证 | covered | 有测试跑到了改动的代码，而且把改动撤掉，这个测试会失败。 |
| 缺少行为验证 | reached only | 测试跑到了这段代码，但把改动撤掉也不会失败：没走到改动的那条路径，或者没检查它影响的结果。 |
| 未找到覆盖 | not reached | 没有任何测试走到这里。 |
| 覆盖待确认 | unknown | 判断不出来。要么 agent 读了测试也下不了结论；要么没有人评估过这处改动，而静态分析没有依据：没找到调用这段代码的测试，或者这段代码已经被删掉。测试仍可能以静态分析跟不到的方式走到它。页面上，结论下面的说明会写明是哪一种。 |
| 覆盖待确认 | called by tests, not assessed | 静态分析找到了调用这段代码的测试，但还没有人读过它们。 |

页面自带的标签只有中文和英文两套。agent 用中文写结果时页面显示中文，其他情况显示英文，和你读的是哪份指南无关。英文的四个结论依次是 Behavior checked、Behavior not checked、No coverage found 和 Coverage unclear。`summary.md` 和 `graph.html` 的标签始终是英文。

风险和流程名称是你的 agent 读代码后的判断。它们不是规则引擎查出来的，名称也不是确认过的需求。

### 做完了没有

地图标着 `partial`（中文页面上显示“部分完成”），说明能用但没做完：有的流程还没描述，描述过的流程还有代码没交代，或者有文件没读。页面上地图规模的旁边会显示这个标记，具体是哪些，`summary.md` 里写着。

地图没有标 `partial`，只说明 agent 计划内的流程都描述完了，不代表覆盖了整个项目。计划之外的东西页面上不显示，要看 `summary.md` 或 `graph.html`：范围（计划了几条流程、覆盖了多少个入口）、被跳过的入口及原因、没处理的入口，以及 “Not expanded” 下面那些只用一步代表的较大函数。agent 没能确认的步骤在做完的地图里仍然保留，带着上面说的标记。

看改动时，页面上不显示状态，`summary.md` 里有两个。“Changes on the map” 下面的 `Status` 说明改动看完没有：缺了该有的东西，比如某处改动还没说明，或者改动落到的流程还只是按代码画的，它就是 `partial`。最上面的 `Map status` 说的是底下那张地图，改动看完了它也可能是 `partial`，比如一次没有描述任何流程的快速答复。

## 把结果发给别人

`view.html` 和 `graph.html` 里带着你的源码片段。要把结果发给别人，让 agent 生成一份用来分享的版本。它会在原页面旁边写出 `view.share.html` 和 `graph.share.html`，不带源码片段。不过流程还没描述的地方，步骤仍然用一行代码来命名；看改动时，改动的那几行也仍然会出现。此外，文件路径和行号、函数名和测试名，以及 agent 写的说明和风险都还在。项目的 `origin` 在 GitHub 上、提交也已经推送时，`view.share.html` 还带着指向这些文件的链接，链接里有仓库名和提交号。

## 再问一次

- 针对已有地图的问题（比如“哪些流程会碰到退款”），agent 直接从已有结果里回答，不会重新分析。
- 代码没变时再要一次地图，会接着上次停下的地方做。代码变了，agent 会重新开始。

## 它在你的项目里留下什么

只有一个目录 `.genesis/`。里面的 `sessions/` 和 `out/` 存着你的源码副本，已经被 `.genesis/.gitignore` 忽略，不要提交也不要公开。Genesis 不改其他任何文件；改代码或改测试，要你另外向 agent 提出。

`git status` 里仍会把 `.genesis/` 列为未跟踪，Git 在里面能看到的只有这个 `.gitignore` 文件。可以把它提交，也可以在项目自己的 `.gitignore` 里加上 `.genesis/`。

每看一次新的改动，或者代码变了之后再运行一次，`sessions/` 和 `out/` 里都会多出一个文件夹，Genesis 不会自动清理。结果不要了，可以把 `.genesis/` 整个删掉，下次运行时会重新创建。

[Genesis EDD](https://github.com/GenesisAgentInfra/genesis-edd) 会特意复制一份：它把 Spec 依据的 `business-map.json` 复制进 Spec 所在的目录，和 Spec 一起提交。这个文件不带源码片段，但还没描述的流程，步骤仍然用代码行命名；它还列出地图读过的文件路径，每个文件带一个内容摘要。

## 语言

Python 的结果最准：Genesis 会自己解析代码、自己找入口，流程里漏了分支，地图就会标成 `partial`（部分完成）。

其他语言靠你的 agent：它来找入口、读代码，Genesis 拿源码核对它写下的每一步。agent 漏掉的路径不会被标出来，它在汇报里会说明这一点。

一次运行只用其中一种方式读项目。项目里既有 Python 文件又有其他语言的文件时，比如 Python 后端加 TypeScript 前端，Genesis 会走 Python 的方式，并统计其他语言的源码文件数：画地图时统计整个项目，看改动时只统计改到的文件。其他语言占多数时，agent 会换另一种方式再跑一次，这种方式覆盖所有语言，包括 Python，只是没有 Python 的解析。否则结果只覆盖 Python 文件，其他语言的改动会列为“未分析”。你也可以直接要求用哪一种方式。两种方式都不读 Genesis 自己的 `.genesis/` 目录，也不读你要求排除的目录：这些文件不计入统计，看改动时报告按目录给出其中改动的文件数。

Genesis 能读这些语言的源码文件：C、C++、C#、Clojure、Dart、Elixir、Erlang、Go、Java、JavaScript、Julia、Kotlin、Lua、Objective-C、Perl、PHP、Python、R、Ruby、Rust、Scala、shell 脚本、SQL、Svelte、Swift、TypeScript 和 Vue。项目里一个这样的文件都没有，就画不了。文件按扩展名识别：.c .h .cc .cpp .hpp .cs .clj .dart .ex .exs .erl .go .java .js .jsx .mjs .cjs .jl .kt .kts .lua .m .mm .pl .php .py .r .rb .rs .scala .sh .sql .svelte .swift .ts .tsx .vue。这些语言里用其他扩展名的文件，比如 .pm、.mts、.cxx，不会被读取。

## 大项目

开始之前，agent 会先数一下 Genesis 要读多少个源码文件，几秒就好。第一步要等一阵子时，agent 会先告诉你有多少个文件、大概要等多久。在 8 核机器上：

| 源码文件 | 画地图的第一步 | 看改动的第一步 |
| --- | --- | --- |
| 约 100 个 | 几秒 | 不到一分钟 |
| 约 650 个 | 约 1.5 分钟 | 约 4.5 分钟 |
| 约 5000 个 | 约 12 分钟 | 约 35 分钟 |

之后 agent 描述流程，还要花它自己的时间。

Genesis 最多读 5 万个源码文件。超过这个数，agent 会先问你：放宽上限、多等一会儿，还是先排除一些目录，比如只看后端。单个超过 1 MB 的源码文件不读，这类文件几乎都是生成的代码或打包进来的第三方代码。因为上限而没读的文件，结果里会写明有多少个，并标为部分完成。你主动排除的目录不算在内：结果只覆盖其余部分，看改动时报告按目录给出其中改动的文件数。

## Genesis 不做的事

- 不运行你的代码和测试，也不读取覆盖率数据。
- CLI 不调用任何模型或服务。读代码的是你自己的 agent，用的是它本来就在用的模型和账号。
- 没有用来发现风险的规则。
- 不记录一个流程怎么交接给另一个流程。agent 可能会在汇报里讲到，那是它自己的理解。
